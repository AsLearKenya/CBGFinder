# 藏宝阁搜索工作台

支持装备、灵饰、上古玉魄、召唤兽、召唤兽装备和角色的筛选与定时搜索，以及已接入品类的估价。当前源码版本为 V0.9（0.9.0）。仓库仅包含本地运行、构建所需的源码和使用说明，不包含账号、任务数据、依赖目录或发行包。

## 桌面应用

发布包自带运行环境，不需要安装 Node.js，也不需要执行 npm start。

- macOS Apple 芯片：解压 `CBG-Finder-V0.9-mac-arm64.zip`，把「藏宝阁搜索.app」移入「应用程序」后双击启动。
- macOS Intel：使用 `CBG-Finder-V0.9-mac-x64.zip`。
- Windows x64：完整解压 `CBG-Finder-V0.9-win-x64.zip` 到一个文件夹，双击其中的 `CBG-Finder.exe`。请保留同目录的 DLL、resources 等文件。
- 最小化使用系统窗口按钮。关闭窗口会隐藏到系统托盘 / macOS 菜单栏，定时搜索继续；点击托盘图标恢复，托盘菜单「退出应用」彻底退出。
- 电脑休眠期间不执行任务；恢复后按调度器规则继续，不补发多次积压请求。
- 桌面版使用固定本地端口 5174，与网页调试版 5173 独立。重复双击只唤起已有窗口。
- Mac 后续构建使用完整本机临时签名以支持原生通知，尚无 Apple Developer ID 公证；Windows 尚无发布者签名；系统可能显示未知发布者提示。macOS 若拦截，在确认来源后通过「系统设置 → 隐私与安全性」允许打开。本机 macOS Apple 芯片已启动验证；Windows 构建完成后仍需在 Windows 真机验收。

### 桌面数据

桌面角色数据保存在当前系统用户的应用数据目录下 `roles/`，网页任务保存在桌面应用的持久化浏览器资料中，安装目录可以只读。应用升级保留用户资料。发布包不包含任何用户账号、密码、Cookie 或任务。桌面应用与原先外部浏览器的资料相互独立，首次启动需添加角色和任务。

开发时先执行 `npm ci` 安装依赖，再执行 `npm run desktop`；构建命令为 `npm run build:mac` 和 `npm run build:win`。依赖版本锁定在 package-lock.json。

## 网页调试模式

```bash
git clone https://github.com/AsLearKenya/CBGFinder.git
cd CBGFinder
npm ci
npm start
```

启动后自行在浏览器打开下方地址。程序不依赖 Ego 浏览器，启动命令不会调用 Ego。

安装 Node.js 20 或以上版本及项目依赖后，在此目录执行 `npm start`，打开 http://127.0.0.1:5173 。网页版界面仍在外部浏览器中使用，后台通过项目附带的 Electron 运行官方页面请求通道；`node server.cjs` 使用同一入口。角色存档仍保存在原 `.data`（或 `CBG_DATA_DIR` 指定目录），任务和浏览记录保留在原浏览器中。需要验证时打开该角色同一会话的官方窗口，完成后在页面点击“已完成验证，尝试请求”。双击 index.html 会跳转到此地址。

## 使用

1. 在“角色管理”添加角色，输入账号、密码及登录区服。建议使用小号，账号需在该服务器下有角色。
2. 登录后选择角色并保存。默认优先选择已知等级不低于 50 的首个角色；列表未提供等级时默认第一个，实际等级在角色登录后读取。
3. 在“任务列表”创建任务并绑定角色。搜索服务器可多选，搜索条件使用官网实时配置。可打开「直接启动」开关，创建成功立即搜索一次；不开启则保存为未启动。创建成功后进入任务列表。已有任务运行中时，新任务排队执行。
4. 开启任务按间隔搜索，或点击“搜索一次”。手动搜索结束后重新开始计时。多个任务排队执行，不重叠请求。
5. 首页只显示调度概况与运行中的任务。任务列表显示全部任务。点击卡片查看该任务最近一轮结果，支持价格排序和结果服务器筛选；召唤兽额外支持造型及成长降序排序。

删除角色会先列出所有绑定任务；确认后停止并移除这些任务，同时删除角色。角色卡片「刷新cookie」可手动更新登录会话。

## 登录与自动刷新

后端完成 URS RSA 密码加密、SM4 参数封装、VDF 校验、票据获取、一次受限的 805/806 校验刷新、藏宝阁登录回调和角色选择。不自动处理验证码、短信或二次验证，遇到这类要求显示失败原因。

任务只提交角色记录 ID，不接收浏览器传入的 Cookie。服务器使用该角色的会话请求官方装备接口。若返回 SESSION_TIMEOUT 等登录超时，刷新该任务绑定角色的会话，成功后重试同一服务器、同一等级分组的同一页。每次请求最多刷新一次；刷新失败或重试后仍登录超时，立即结束本轮任务。已有成功页保留，结果标明未搜完整。普通网络或筛选错误不会自动重新登录。

刷新开始、成功、失败和重试均记入“运行记录”和对应任务详情。刷新始终登录保存的具体角色，不替换为其他角色；该角色不存在或不可登录时直接失败。

## 数据保存

- 角色账号、密码、会话及刷新记录加密保存到项目 `.data/roles.enc`。AES-256-GCM 密钥位于同目录的 `key`，文件以本机权限创建（POSIX 下目录 0700、文件 0600）。这不是操作系统钥匙串；不要共享整个 `.data` 目录。`.data/` 已加入 Git 忽略。
- 浏览器仅获得公开角色资料，不获得密码、登录票据或 Cookie。登录草稿只在服务器内存保留 10 分钟，可在选择角色前取消。
- 任务名称、角色绑定、服务器、间隔、筛选条件和启停状态保存在同一浏览器、同一地址的 localStorage。旧任务继续保留，未绑定有效角色时暂停，编辑绑定后再运行。
- 搜索结果按任务隔离，在当前页面内存保留，刷新后需要重新搜索；刷新记录保存在本机。新搜索不会清空其他任务的结果。
- 自动任务在页面打开期间执行，关闭页面时停止；重新打开后已启用任务从完整间隔重新计时。
- 清除网站数据会清除任务；删除 `.data` 会清除角色登录记录。

## 搜索范围

每个区服和等级分组从第 1 页开始逐页取完，每页 15 条，无总页数时取到不足一页为止；页与页之间间隔 1.1 秒。重复页、错误分页或请求失败会明确标记未搜完整。跨页结果按区服和商品编号去重，不包含模拟商品。

服务器和全品类筛选配置每次打开页面都从官网刷新。服务器选择右侧有大区拼音首字母定位索引。切换浏览器窗口不会重新加载角色。装备类型、特技、套装支持多选，价格和等级范围使用手动输入，参数由 `search-params.js` 统一构建，金额从元精确转换为分。

## 验证

`npm run check` 检查脚本语法，`npm test` 运行测试。代理路由测试直接执行请求处理器，无需监听端口；其登录和搜索响应为隔离的测试替身，不会调用真实账号，也不会生成默认角色或任务。

## 召唤兽搜索

筛选顺序与提供的官方截图一致：价格、等级、参战等级、宝宝、分类、技能、赐福技能、不含技能、概况、类型、神兽星级、资质、属性、特性、内丹和梦影。技能分高级物理/法术/通用、特殊、超级和初级；名称、ID、图标和类型来自官网配置。包含/排除技能互斥，选中一侧会取消另一侧相同技能。分类按官方类型名称分组并解析为真实 type ID，具体类型可继续收窄。

金额按元转分，成长按千分值构造参数；赐福满足一种对应 evol_skill_mode=0，全部满足对应 1。每个服务器独立逐页搜索，沿用绑定角色的 Cookie 与登录超时刷新处理。内丹数从官网 large_equip_desc 中的 summon_core 明细统计并在每页返回后筛选，原始页数与翻页条件保持不变，不发送未经确认的内丹数量参数。

召唤兽展示解析描述中的等级、技能、资质、属性、成长和内丹种类/层数；解析描述使用严格的数据扫描，不执行官网描述文本。

## 角色搜索

角色搜索使用 `recommend.py` 的 `overall_search_role`，沿用绑定角色的共享 Cookie、每服务器完整分页、排序、任务存储和定时执行。筛选项根据官方 `overall_search_role.js` 和用户提供的请求映射；门派、造型和施法特效来自官网公开 `game_auto_config.js` 字典，祥瑞、锦衣与挂件来自实时加载的筛选配置。金额以元输入、按分发送；总经验以亿输入。性别转换为真实造型 ID 范围，与造型条件取交集。

本次暂不提供角色属性、身上召唤兽、神器、孩子、可转服务器条件，也不加载角色详情。列表参照官方显示门派、等级、最高飞升阶段、成就、修炼概况、官方参数标签、交易标识、服务器、价格及上架时间；化圣优先于渡劫，渡劫优先于飞升，保留化圣层数。范围输入的快捷选项已移除，旧装备任务的离散等级仍保留，手动输入新范围后替换。

品类搜索不选择服务器时代表全服：请求直接省略 `serverid`，沿用官网返回的分页；选择部分服务器时仍逐服搜索。登录角色所需的服务器仍需明确选择。任务调度器与搜索参数共用支持品类定义，装备、召唤兽、角色均可手动执行、启动及定时执行。

每个任务部分区服最多8服，勾选全部服务器时转为省略 `serverid` 的单一全服查询。每个任务最多同时推进3个服务器，各服务器内部顺序翻页，默认 `order_by=price ASC`。取消200条上限，取完所有分页；分页过程中保留上次结果和本次已取得的数据，单服全部成功后更新该服快照。失败服务器可单独补搜，其余服务器不重复搜索。同一任务上一轮尚未结束时跳过新触发。

同一角色绑定任务数量不限，最多开启3个任务，共享后端 FIFO 请求队列（包含商品详情和搜索的重试）。同时最多2个请求，请求启动至少间隔1秒，各角色独立。旧存档超过3个已开启任务时保留前3个开启，其余保留条件并暂停。2026-10-23 在用户完成官网验证码后，以1～4并发各两轮共20次只读请求测量，全部成功，耗时约257～478ms；因此留余量采用2并发。这是短测后的保守配置，不是官网保证的长期阈值。遇到验证码或HTTP429，立即停止该角色队列，需用户处理并手动刷新Cookie后恢复；不自动重试验证码。所有任务继续共用角色原有的Cookie刷新和失败重试计数。

验证处理：启动时按任务原条件请求一页，确认是否仍需验证。桌面版点击「在当前会话中验证」，独立官方窗口沿用任务角色 Cookie，支持输入将军令或手动完成官方滑块验证。完成后点击「已完成验证，尝试请求」，同步当前会话并请求任务原条件，不重新登录。窗口关闭或 Cookie 同步本身不代表验证通过，仍需实际请求成功才清除错误并恢复任务；暂停任务保持暂停。外部浏览器会话与程序独立。

筛选编辑器：装备、召唤兽、角色的已设置条件，在左侧分组及分组标题显示红点，输入、取消选择、清空后实时更新。仅切换默认匹配方式不算已填写条件；0阈值、0星等有效值仍标记。结果区支持价格升降序，召唤兽另支持造型（携带等级从高到低）及成长降序；可按结果中的服务器筛选，默认全部服务器；筛选按任务独立保留，不改变任务条件、不重新发起搜索，也不丢弃已缓存结果。

召唤兽装备品类：使用 `overall_search_pet_equip`，支持5～145级、附加状态/无套装/可覆盖套装、护腕/铠甲/项圈、装备属性、精魄灵石、六种附加属性、属性总和（含伤害）、敏捷减少和修理失败次数。类型及字段来自官方搜索页与公开配置，沿用全服/部分区服、完整分页、角色共享请求队列和服务器结果筛选。列表展示等级、合并镶嵌后的属性、套装及交易信息，制造者与原始镶嵌信息放在展开详情中。召唤兽详情的每件装备在折叠栏直接显示套装，展开后共用同样的官方风格详情卡片。

任务编辑：即使尚无角色或现有角色任务名额已满，也可先填写任务并设置筛选。绑定角色旁可直接添加角色，保存后自动绑定并返回原任务；取消添加也保留原任务草稿与服务器选择。任务编辑使用同一窗口左右分栏，左侧固定基本设置，右侧直接展示当前品类筛选，顶部分类快捷定位、已填红点与清空入口，只有筛选主体纵向滚动。窄窗口或低高度窗口改用整页统一滚动。装备套装及新增角色往返保留草稿，最后统一提交保存。

任务服务器选择：在任务字段旁的下拉面板中沿用共享服务器组件，按大区分组，支持服务器名称、拼音、首字母、大区名称及大区拼音检索，并保留大区首字母定位、最近5条选择和多选。部分区服最多8个；一键清空后不选表示全服。确认或收起时保持在同一任务窗口，任务名称和筛选条件保留，保存任务才持久化。角色登录继续使用同一组件的单选模式。

服务器下拉面板优先铺满任务编辑器右侧的可用区域；窄窗口改用视口内的宽面板。最近选择自动换行，首字母索引置于列表上方完整展示，面板内仅大区列表纵向滚动。

灵饰品类：使用官网 `overall_search_lingshi`，等级字段为 `equip_level_min/max`（60～160），支持戒指、耳饰、手镯、佩饰、基础属性、每组3条可重复附加属性、综合属性、套装及等级、精炼等级、修理失败上限、超级简易。附加属性按 `added_attr.N` 计数，综合属性使用 `synthesized_attr_total` JSON；选项来自公开 AUTO_SEARCH_CONFIG。沿用完整分页、服务器选择、角色共享限流和详情展开缓存。列表合并精炼增量，详情按官方描述分开展示。未使用用户粘贴的Cookie；匿名接口核对返回登录过期，真实账号搜索仍需在程序内绑定角色。
装备修理失败改为无失败、≤1次、≤2次、≤3次的单选按钮，0值正常保存并发送，按上限筛选。

服务器选择移除全选入口，使用一键清空取消全部勾选；保留搜索词与面板，确认后按全服搜索。最近记录读取时将旧记录裁剪为5条，保存时去重并保留5条。组件内部重绘后，外部点击判断使用原始事件路径，避免把已经脱离DOM的按钮误判成外部点击而取消选择。灵饰列表只展示基础属性、精炼等级、附加属性与真实特效，去除通用宝石、耐久、修理失败列表文案；详细原始参数仍在展开详情中保留。

## 本地数据路径

桌面版在系统设置中展示数据存储路径，可选择空目录。重启时复制并校验角色、任务、浏览器本地存储及搜索快照，原目录保留。迁移失败继续使用原目录。首次启动显示可跳过的路径设置提示，后续启动不再显示。

## 验证状态恢复

启动后对上次被验证码拦截的角色先请求一页确认当前状态，同角色合并检查，30秒内不重复。任务页也可点击“尝试请求”。正常返回时清除旧验证码状态；当前响应为将军令等账号安全要求时展示对应提示，不再误当作验证码处理。

## 召唤兽成品 / 胚子筛选

筛选支持「不限 / 成品 / 胚子」单选，使用官方 `pet_sub_type` 参数（胚子为 1，成品为 2），保存到任务，并随各页请求发送。

## 装备列表初始属性

宝石只影响总属性，不改变初属性。列表仅在有对应宝石加成时补充初属性：武器有太阳石时显示初伤，有太阳石或红玛瑙时显示初总伤；项链有舍利子时显示初灵；男衣或女衣有月亮石时显示初防。初属性采用接口返回值，不重复扣除宝石或叠加熔炼；缺失值不估算。

## 召唤兽列表摘要

召唤兽列表在等级下方显示成长（保留三位小数）和技能数。优先使用接口或官方摘要中的技能数；缺失时从返回的技能条目统计，接口未提供时显示“—”。

## 召唤兽结果排序

结果列表支持价格升降序，以及固定降序的造型（携带等级从高到低）和成长排序。造型按官方类型等级映射排序，同级按造型归组，同造型按价格升序；成长相同时按价格升序。缺失等级或成长的数据放在末尾。召唤兽排序与其他品类的价格排序分别保存，互不覆盖。排序只作用于当前结果，不改变搜索条件和请求顺序。

## 页面恢复与排序位置

官方浏览器通道在复用页面前检查 `Request.JSONP` 是否就绪；新页面允许短暂等待脚本初始化。官网繁忙或组件缺失时最多重新加载一次，错误页不会进入可用页面缓存，之后手动重试会重新加载。将军令、验证码和登录过期保留真实状态码，交回已有会话处理流程，不当作普通加载失败重试。

主动切换造型、成长或价格排序保持当前滚动位置，不再追踪排序前的商品；后台分页和数据更新仍保护当前浏览的商品及展开详情。显式排序时暂时关闭浏览器原生锚点补偿，覆盖整页滚动和内部结果区滚动。

曾通过对照复现中文应用名称加入 HTTP User-Agent 导致 `e-b-1008`；替换非 ASCII 应用产品名为 `CBG-Finder` 后当时搜索恢复。这不是该错误码的唯一原因：2026-10-29 已确认使用修正后的浏览器标识，同一会话的装备页、召唤兽页和推荐页仍会返回无脚本的 `e-b-1008` 错误页。这类反馈码没有直接说明 Cookie 失效。用户随后确认，官方 App 出现相同问题时完成将军令验证即可恢复，因此本地将 `e-b-1008`、`eb-re410` 作为“可能需要将军令验证”的恢复规则，提供当前角色同一浏览器会话的官方验证窗口。提示保留原始反馈码并注明本地推断；不自动完成验证、不重新登录，仍须实际请求成功才确认恢复。

除上述已纳入将军令提示的反馈码外，官网搜索页面连续两次加载失败，或搜索接口返回其他 `ERR` 系统繁忙后，同一角色的搜索和估价共享 30 秒冷却，期间不继续加载官网页面或重复发起搜索；其他角色不受影响。用户完成官方窗口验证、同步新会话后可以立即检查恢复状态。页面错误通过 HTTP 503、真实原因和重试间隔返回，因同轮失败而停止的服务器显示原始失败原因，不再统称为“角色会话失败”。冷却结束不等于官网恢复，仍需实际搜索成功确认。

验证窗口若返回 `eb-cgl4101` 等官网错误，界面会明确提示“尚未进入验证”。返回地址 Cookie 按官网方式清理路径并编码，跳转携带来源页；支持在同一角色浏览器中重试密保页、打开官方搜索页或官网登录入口。官网登录入口使用绑定角色的区服，不清空原会话。同步后仍以原任务真实请求判定是否恢复，打开窗口或错误页不代表验证通过。

装备时长估价：前 5 天不折价；此后时间比例为 `1 − 20% × ((上架天数 − 5) / 12)²`，第 17 天为 80%，临近下架折价增幅更大。样本挂牌价先乘时间比例，再扣宝石、开孔及还原失败折价。前 5 天参考估价高于本件挂牌价时，仅标注“低于同类在售价格”；第 6 天起建议价为 `min(样本估价，本件挂牌价 × 本件时长折扣)`。缺少时间时不套用本件价格上限。

消失商品卡片统一采用官网状态查询结果，隐藏旧搜索快照中的在售标记、公示及剩余时间；显示核对时间并支持手动重新核对。未知或查询失败时显示待确认，不沿用上架状态。估价基准标明实际相近报价数量；挂牌时长仅作为补充依据，不使用“可能是正常价格”替代具体证据。

易修理（官网特效 14）仅在该件装备等级 ≥100 且修理失败为 0 次时参与重要特效匹配；失败后的该特效忽略。无失败易修理样本不能用于普通装备的估价，无失败易修理目标仅用同类无失败易修理样本，远端查询同时要求修理失败 0 次；该特效不支持降级忽略。

附加属性侧重仅应用于武器和铠甲／女衣，其余品类忽略附加属性。侧重项作为硬下限：样本该项必须 ≥ 本件 −1，总和较高或其他属性较高也不能抵消超过 1 点的缺口。只要存在侧重属性，附加属性总和也必须 ≥ 本件总和 −1；没有侧重属性时仍允许总和 −2。属性组合一致、总和分档、基础属性、重要特效与套装等条件仍同时成立。按每件目标商品的宝石、实际附加属性和初始属性判断，不按任务选择推断。

- 武器含红玛瑙（含混搭）按物理方向，侧重实际携带的力量、敏捷；纯太阳石按法系方向，侧重魔力、敏捷。含任意非太阳石宝石不能判为法系；既非红玛瑙又非纯太阳石的组合暂按平级规则。无宝石时力量／魔力／敏捷同级优先，其次体质、耐力。无宝石力魔双加按初伤 ≥ 强化伤害上限 ×0.86、初总伤 ≥ 强化初总伤上限 ×0.9 分别判法系／物理；两者均满足时点数较高项须比另一项高至少 20% 才区分，否则平级；两者均未满足或缺少初始属性时按平级规则。
- 铠甲／女衣纯舍利子侧重魔力、敏捷；含任意非舍利子宝石不能侧重魔力，按敏捷、力量、体质、耐力排序。无宝石时力量、敏捷、魔力平级；双加仅含这三项时，较高项 ≥ 较低项 ×1.2 才侧重较高项，否则平级；与体质或耐力搭配时侧重实际携带的前三项。侧重只取本件实际拥有的正属性，负属性仍保留在组合与点数匹配中。

强化武器范围固定保存在 `weapon-forging-ranges.js`，来源：[网易官方工具箱](https://xyq.163.com/tools/index.html)“装备打造属性／强化打造”，核对日期 2026-10-30，保存来源哈希，不随时价更新。60～160 每十级一档，包含伤害及命中上下限；最高初总伤按 `最高伤害 + 最高命中 / 3` 计算，不先取整。120 级强化伤害 388～505、命中 451～586，因此分类阈值为初伤 434.3、初总伤 630.3。宝石方向优先于无宝石分类阈值。武器和铠甲／女衣若同时选出两个侧重属性，则改按平级计算，不施加侧重单项与总和 −1 下限；沿用平级总和分档和单项偏差。只有一个侧重属性时仍执行侧重单项与总和 −1 下限。估价依据显示侧重原因与“重点”标记，共享查询与材料报价机制保持不变。

装备两套开运分别按对应等级满孔金额计价后相加；未满孔的一套不计价。样本白板反推和目标加回使用同一套规则，宝石封顶仍不包含任何一套开孔。兼容旧结果描述中的双套标记，不将“4孔/4孔”当成两套。

项链初灵前三档统一允许向上 2 点（可跨到更高档），向下仍保留原来的 0、1、2 点偏差和各档下限；第四档保留原 ±3 及档位上限。例如 120 级初灵 190 可匹配 190～192，189 可匹配 188～191，179 可匹配 177～181。

装备、灵饰和上古玉魄支持“溢价率从低到高”：以（标价－参考估价）÷参考估价计算，显示与排序采用同一个参考估价（包含本件挂牌时长上限）。粗略估价共同排序，暂无有效参考估价的商品置后。列表只显示挂牌价和参考估价，样本参考价、孤立低价、材料价格及跨服费用放到依据或商品详情中查看；粗略估价仍提示误判风险。

灵饰有两条及以上同名副属性时，比较对应词条的数值总和，合计容差与该属性单条容差相同，不随条数放大。前排速度合计允许向上0～2，其余副属性合计±2；后排气血合计±10、防御／法防合计±2、格挡值／抗封／回复合计±3。重复词条的种类和数量仍须一致，主属性与其他词条规则保持不变；依据表合并显示同名属性合计。

后台搜索、估价与启动恢复使用增量界面更新：侧边栏、任务卡、角色卡及表单控件保留节点，避免鼠标按下和松开之间被整体替换而丢失点击。网络进度更新合并为短周期刷新；排序仍按用户操作保留视窗位置。顶部状态显示正在恢复的数据、材料报价准备、搜索任务和估价任务，状态出现或消失不移动页面内容。角色列表后台重读时保留已显示的角色；恢复磁盘估价记录不会覆盖正在计算或刚完成的新估价。装备估价设置的未保存输入保留在界面草稿中，保存或恢复默认时才提交／清除。

灵饰前排三条副属性全部属于同一组别时，样本必须完整匹配三个词条的种类与重复数量，不降为两条组别匹配；数值沿用品类容差与重复属性总和规则。超级简易仅在80、120、140、160级参与样本比对与取样条件，60、100级忽略。

前排副属性容差：样本速度减商品速度须在0～2之间，不接受低于商品的速度；其余属性允许±2。同名属性重复时按总和应用此范围，主属性与后排容差保持原规则。

灵饰三条同名副属性优先匹配：不受前后排组别或档位匹配限制，样本必须为同一种属性的三条，不接受两条或其他同组属性替代。比较三条的数值总和，容差使用该属性单条标准，不乘以3；沿用主属性、等级、修理失败、超级简易及价格门槛。


### 上古玉魄估价

任务列表可独立开启上古玉魄估价，也支持在估价页面输入商品详情链接。阴阳分别全服采样，沿用三小时缓存、逐件展示、材料日缓存与用户定价、价格佐证、最低有依据折算价×95%及挂牌时长折价。挂牌低于50元不估价，无修理失败及开孔折价。

列表与估价均使用一条主属性与两条副属性的灵尘加成前数值。未提供灵尘等级按0段处理，0段不在列表显示。三条同名仍要求样本三条同名；重复词条比较总和并使用单条容差。阴阳玉的一级属性均不可替换；二、三级仅允许主属性同级替换，所有参与计价的副属性保留同名。主副或双副重复词条保留，未计价的无效属性位置不限，允许样本在该位置带更好的属性。阳玉未参与组合的第三条仅治疗／封印计价；阴玉三条有效时保留档位分布，换成同级不同名的主属性只核对档位，不直接比较数值。先天奇袭法术概率容差为±0.1个百分点，不计五色灵尘提供的概率。官网结构化详情的effect.desc是先天特效，effect.desc2是灵尘加成，分别读取，避免误取加成或重复扣减。灵尘2／6／8／12／14／15段的累计加成为0.5%／1%／2%／3%／4%／5%，依据[官网命魂之玉说明](https://xyq.163.com/news/20250416/4999_1227842.html)；只有合计数值时才扣除加成。法系阳玉计物伤化劲，其他组别阳玉与阴玉计物伤化劲、法伤化劲，化劲容差均为±0.5个百分点；计价特效须与样本有无一致，其价值通过同类样本体现，不另加固定金额。法系组别以参与计价最多的有效词条判定，存在其他同等有效组别时不会仅按法系忽略法伤化劲。

阳玉速度允许向上0～2，其余±2；阴玉气血±12、防御±4、法防±6，格挡值／抗封／回复±8。五色灵尘按绑定角色所在服报价累计至实际镶嵌等级，自带额外灵尘等级不计材料价。白板＝挂牌×时长比例－样本五色灵尘；换算＝白板＋本件五色灵尘，沿用材料计价比例与1.2倍价值上限。依据直接展示样本详情和属性对照表。

齐天小圣锦衣与祥瑞均归入官方赠送名单，不使用默认限量单价；估价明细保留零元赠送说明。

验证恢复：用户完成将军令／滑块验证，或主动尝试请求确认会话恢复后，同绑定账号所有已开启任务立即搜索一次；已暂停、正在执行及其他账号任务不重复启动，仍沿用角色请求队列限流。启动时的后台验证状态检查只恢复计时，不批量立即搜索。

普通装备挂牌价低于50元不估价，50元起仍可估价。低价目标不生成估价采样范围；全组低于门槛时不发起材料或全服估价请求。列表隐藏旧估价并从溢价率计算与排序中排除。


### 角色携带物估价

角色底子及外观估价完成后，如详情中有可估价的装备、灵饰、上古玉魄，列表提示“有装备、灵饰、上古玉魄未估价”，由用户点击“估价携带物”启动。按品类、等级与武器比对维度合并范围，复用当前全服样本、材料日报价及折算规则；不自动估价召唤兽、法宝、材料或不支持等级的装备；整卖角色包含拆卖物品，拆卖角色排除这些物品。

未独立挂牌的携带物只对样本做挂牌时长折价，不套用账号挂牌价或账号剩余时间。有独立商品编号的物品先请求其独立详情，用真实挂牌价与剩余时间应用当前估价上限，并在明细提供独立商品链接；读取失败时注明原因，回退至普通携带物估价。单件参考估价小于50元不计入，50元及以上加入角色估价合计。明细单列携带物小计、各件计入金额和样本依据，图片同步展示。支持逐件更新、停止并保留已完成结果，任务编辑或规则／材料价格变化后旧估价失效。

角色自动估价仅在卡片摘要至少四分之一可见并连续停留600毫秒后触发，不再提前300像素预加载。滚出视窗、切换后台或卡片被移除时取消等待；串行详情队列真正发起请求前再次检查可见状态，已离开的角色跳过并可在返回时重新触发。手动展开详情仍立即加载。

手动携带物估价使用交互优先队列，详情、全服采样和所需材料报价排在未开始的后台请求之前；已发出的请求不打断，并发上限、请求间隔和验证暂停规则保留。携带物不等待全部区服／全部材料批次，按需优先补齐本服对应材料；与后台共享每种材料每个等级的当日报价及在途请求。列表显示当前独立详情、材料或采样阶段。

结果排序按品类独立保存到本地：角色、装备、灵饰、上古玉魄、召唤兽和召唤兽装备互不影响。同一品类的任务复用该品类偏好；未设置时默认价格从低到高。召唤兽造型／成长和装备类溢价率选项仅在对应品类使用。

携带物整轮估价完成后，列表仅提供“查看携带物估价”，未匹配到样本也视为本轮已处理，不会再次发起采样。未估价项及数量提示标红，粗略估价标黄；按规则不计入价值的项目仍置灰。角色明细和生成图片使用相同标记。

携带物估价完成后，角色列表显示绿色完成提示及逐件编号索引。点击“查看携带物估价”定位到明细区，点击编号直接定位并聚焦对应物品；索引同样标示未估价红色、粗略估价黄色。快捷入口只导航，不重新采样，也不触发角色详情展开。

角色专用装备不估价，也不作为其他装备的参考样本。携带物中标记为角色专用的装备直接跳过采样，明细置灰并注明“角色专用装备，不估价”，不计入账号总价。列表、链接估价和后台估价接口采用同一规则。

任务确认已售出的商品按任务保存到本地，保留最后见到的挂牌价和商品属性，重启及查看变化后仍可使用；任务编辑／删除时随任务记录清除。下架、待付款或状态不明不算已售出，重新出现在结果中的商品移除售出记录。

装备、灵饰、上古玉魄（含角色携带物）估价时，已售出商品须符合该品类现有属性匹配规则；已售出商品标价低于当前计算估价20%以上时排除，恰好低20%可用，向上不限制价差。最终价格＝min(当前参考估价，符合上述价差范围的已售出商品中最低的最后挂牌价×95%)；仅在采用已售出价格作为定价标准时显示“精确估价”，否则保留参考估价及原有粗略标记。溢价率和排序使用最终价格。当前参考估价已经包含原有95折与时长上限，不再追加95折。依据列出已售出商品和属性对照；最后挂牌价不代表实际成交价。角色底子估价仍沿用本地计算规则。

装备与灵饰共用按等级分档的修理失败计价比例（可在估价设置修改）：100级以下为100%／95%／90%；100～120级为90%／80%／70%；120级以上为90%／70%／50%，依次对应1／2／3次失败，无失败始终100%。样本范围按目标等级和失败次数判定：100级以下≤2次互用，3次可用全部；100～120级≤1次互用，2／3次可用全部；120级以上≤1次互用，2次仅用≤2次，3次可用全部。采样请求、缓存覆盖范围、已售出佐证及角色携带物均使用相同限制。灵饰列表不展示0级精炼。

材料价值上限倍数可在“估价 → 估价设置 → 装备 → 宝石价值上限”自定义，默认1.2倍，保存后本地持久化；装备宝石、灵饰星辉石及上古玉魄五色灵尘沿用该共用上限。比较基准仍为修理失败折价后的装备价值，不包含宝石、开孔；样本反推白板价格和目标材料加价均使用所设倍数。

灵饰与上古玉魄的同名属性比较包含主属性：同名主、副属性累加后使用该属性单条容差，容差不乘条数，也不分别限制主、副属性的数值。词条类型、数量、主属性类型及有效组别规则仍保留；主属性没有同名副属性时沿用原有独立数值规则。灵饰遇到主副同名时，官方采样不再设置主属性数值下限，避免遗漏主属性偏低而副属性补足的样本，最终本地核对总和。

灵饰只使用同等级样本，取消所有向下取等级采样；已售出价格佐证同样只匹配同等级。主副同名属性仍合计比对，数值容差、失败次数和特效规则不变。采样将每种有效词条的数值下限放入综合属性参数，数值范围明显分离时拆组。

灵饰／玉魄采样按页评估：至少5件有效样本且按现行价格佐证规则算出估价，才将该目标移出待采样集合；只有属性命中而没有可用报价佐证时继续翻页。已完成商品不再单独驱动查询。灵饰共享请求的主属性下限可随剩余目标收窄，至少上调2点才重建，每条共享查询最多收窄3次，减少频繁重开带来的开销；无法用官方参数表达的范围仍在本地比较。参数改变后使用独立分页游标，从第一页读取；相同参数复用分页位置与完成状态。整轮商品按服务器及商品编号去重，跨查询返回的同一商品不会重复计入样本或重复请求材料。进度显示具体类型／等级、页码、采样次数、已完成目标数。

每个角色绑定任务数量不限，但最多只能开启3个任务。开启第4个任务会提示先关闭其他任务，不进入运行排队。新建直接启动、已开启任务改绑角色及全部开启也遵守此规则；恢复旧存档时保留前3个已开启任务，其余保留但暂停。不同角色独立计算。未新增任务执行并发限制，原官网请求并发数和间隔保持不变。

样本白板＝（挂牌价×时长比例－精魄灵石－点化石）÷失败比例；再换算成本件失败比例、精魄灵石和点化石。失败次数的折扣与样本限制沿用人物装备，装备等级向下取整十位后分档（125级按120级）。最终价格沿用现有最低价佐证、95%参考比例、挂牌时长上限与已售出价格佐证规则；列表逐件更新，依据展示样本详情及折算式，支持溢价率排序。

### 任务导入与导出

任务列表顶部“导出任务”可勾选一个或多个任务，复制JSON文本或下载JSON文件；“导入任务”支持粘贴JSON，也可同时选择或直接拖入多个JSON／TXT文件；拖入文件后仍需点击“导入并编辑”检查并创建任务。格式为 `{"format":"cbg-finder.tasks","version":1,"tasks":[...]}`。每个任务包含名称、品类、区服、搜索间隔、该品类的全部筛选参数；不包含绑定角色、账号凭据、开启状态、估价及通知开关、任务编号、运行记录或搜索结果。

导入后按顺序进入新建任务页，默认不启动任务；第一项需自行选择绑定角色，后续项沿用本轮已选择的角色并允许修改。每项检查后点击创建才保存，也可跳过；关闭编辑窗口会结束本轮尚未完成的导入，已创建任务保留。导入始终创建新任务，不覆盖已有任务。区服优先按名称与编号匹配当前资源；无法匹配会提示，须重新选择或清空，不自动改为全服。任务数量不限，同一角色最多开启3个任务的规则仍有效。文件总大小最多5MB，每次最多1000项任务。


装备、灵饰、上古玉魄、召唤兽装备估价按目标挂牌价与还价状态选择采样方式：低于200元直接指定服务器查询；低于400元且可还价，也直接指定服务器查询；200元至不足400元且不可还价，先跨服查询，有效样本不足5件时再补指定服务器；400元及以上使用跨服查询。补查时保留已有合格样本，统一去重。任何采样来源、缓存或已售出佐证中，标价恰好200元的异服商品均不可作为样本；本服标价200元仍可使用。未单独挂牌的携带物沿用原采样方式。

指定服务器按用户提供的神区、第一、第二、第三梯队共53个服务器依次查询，每个服务器内按价格升序翻页，最多到水泊梁山；取得5件有效样本即停止，少于5件仍按既有粗略估价规则处理，不查询第四梯队及之后的服务器。当前服务器显示在采样进度中。相同参数合并查询，跨服务器／查询结果按商品唯一标识去重，缓存仍为3小时。玉魄在当前服务器的两种副属性顺序、允许主属性替换各路查询完成后才可提前停止；同名主副属性仅设合计下限，避免遗漏数值重新分配的样本。

孤立低价补充规则：最低样本折算价与待估商品挂牌价的绝对差额，不超过挂牌价的10%时，可直接作为定价基准；参考价仍为该折算价×95%，并继续应用本件挂牌时长上限。该结果标为粗略估价，依据标注“与本件挂牌价相差不超过10%”。无独立挂牌价的角色携带物不使用此规则，独立挂牌的携带物可使用。

钟灵石报价补缺：烈火燎原、参天古木为一组；金石之坚、波浪滔天、水来土掩为一组。某款没有可用报价时，取同服务器、同等级下同组最低有效报价（含可可靠换算及用户定价），标为“同组补价”并注明来源。自身已有报价或用户定价时不替换，同组均缺价时仍保留缺价。

星辉石当日5～10级中某级缺货时，按同服已有可靠报价依3合1换算，标注“当日缺价换算”；已有直接报价不覆盖。灵饰、玉魄及召唤兽装备的中断采样会保存各查询分页进度，后续估价可从失败页继续，不把未完成缓存视为已完成。列表对未完成采样提示查看依据。

高价商品采样：独立挂牌价格达到5000元时，采样目标改为3件，价格佐证需另外1件；5000元以下仍采5件，样本不足5件时需另外1件、达到5件时需另外2件佐证。价格佐证容差仍为20%，孤立低价10%规则、95折及时长上限不变。规则同步用于装备、灵饰、上古玉魄及召唤兽装备；没有独立挂牌价的角色携带物仍采5件。

粗略估价有效性：按参考估价计算溢价率，若（挂牌价−参考估价）÷参考估价低于−20%，且没有已售商品佐证形成精确估价，则显示“样本不足”，不展示该估价和溢价率，也不参与有效溢价率排序；样本依据保留。恰好−20%不触发。无独立挂牌价的携带物不适用。

官方明确提示账号保护性冻结或封禁时，标为ACCOUNT_RESTRICTED并暂停该角色后续请求。启动时不自动探测已保存的冻结状态，用户处理官方安全状态后可手动检查。

装备套装比对按本件用途过滤：明确判为法系时忽略逆鳞、变身、杀气诀、碎星诀、满天花雨；明确判为物理时忽略定心术。用途未明确时保留原套装规则；该规则同时用于采样条件与样本匹配。

估价采样按整个任务的商品总数选择策略（装备、灵饰、上古玉魄、召唤兽装备通用）：少于100件逐件取样；100～299件每组最多3件；300～499件每组最多5件；500件及以上保留原分组策略。先按品类、等级、重要特效／技能／套装等硬条件隔离，再按模糊范围及属性数值的相近程度分组，不能为了凑组放宽样本匹配规则。小任务每件凑齐5件符合现有容差和折算条件的样本后停止采样，价格分散不足以佐证时保留“样本不足”等原因，不为强行给价继续翻页。500件及以上保留原有高价商品3件、其他商品5件的目标。

同一任务共享原始样本库：正常搜索结果和所有估价查询返回的商品均保留，不限于最终参考样本；后续商品先本地匹配，够用直接估价。按商品ID去重，重复请求返回同一商品时更新资料，不重复计数；不同参数查询仍复用分页缓存。样本库按任务、角色、服务器和筛选参数隔离，在数据目录的 `*-task-samples.json` 持久化，每条样本有效3小时；宝石、失败、挂牌时长等价值使用当前规则重新换算。新策略不增加并发请求。

任务内二次复核：挂牌价低于200元的商品跳过复核，保留原估价；200元及以上才参与。整轮估价完成后，在本地为粗略估价商品寻找本任务中已经得到精确／参考估价的可比商品，不新增请求。只比较同等级、同品类扩大组、相同重要特技／特效／套装和相同附加属性类型的商品；物理武器仍把力量折算进总伤。逐项数值全面不差时建立价格下界，全面不优时建立上界；有高有低的属性组合不强行排序。灵饰、玉魄、召唤兽装备也保守地要求词条身份与数量一致，避免混用不同词条的价值。

对比价格先剥离材料、开孔与修理失败折价，再按本件配置换算，并遵守本件挂牌时长上限，不再打95折。仅双侧上下界一致且上界不超过下界20%时生成“复核参考价”：原粗略价在区间内则保留，超出则收敛到区间边界；原来没有价格时取区间中点。单侧依据、区间过宽或上下界冲突时，仅展示上下界、逐项属性对比及对比商品的估价入口，不强行给单一价格。复核结果保留粗略性质，不能成为下一件商品的定价依据，也不标为精确估价；原有粗略估价偏差过大规则仍然生效。复核结果随任务估价保存；商品或对比依据发生变化时不再套用旧结果。

金刚怒目：武器、铠甲和女衣仅在侧重敏捷，或没有侧重属性且拥有正敏捷附加属性时计入价值；侧重其他属性或没有正敏捷时忽略。其他部位沿用原特技规则。该判断统一应用于采样参数、样本匹配、已售出佐证与任务内二次复核。
